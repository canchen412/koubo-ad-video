# 配音断句：两道闸门（前置扫描 + 听写回验）

> 立规日：2026-11-11。起因是老板验收 261111 那条蛋白吐司时的一句原话：
> 「结果配音说成了：早上搭一杯咖啡，练完饿了撕，两片都不用开火动锅。
>  其他地方偶也类似的问题，你看什么情况，**以后不要犯类似的错**。」

---

## 一、这不是切句错，是文案本身有歧义

排查顺序（按这个顺序走，别一上来就怪脚本）：

| 环节 | 实际情况 | 结论 |
|---|---|---|
| `phrases.txt` 切句 | 一字不差，就是「……练完饿了撕两片，都不用开火动锅。」 | 不是切句错 |
| 标点 | 逗号位置正确 | 不是标点错 |
| 合成方式 | `tts_split_cloud.py` 逐句合成，这一句是**一次请求**送进去的 | 不是拼接错 |
| 服务端时间戳 | `「撕→两」gap 73ms`，和普通音节一样 | 时间戳是强制对齐的，掩盖了真实停顿 |
| whisper 独立听写 | 明确切成「练完饿了撕」／「两片都不用开火动锅」 | **停顿真的落在「撕」后面** |

**真因**：「撕两片，都不用开火动锅」里的「两片」

- 往左看，是「撕」的宾语 → 撕两片（面包）
- 往右看，是「都不用开火动锅」的主语 → 这两片都不用开火

中文里两个读法都成立。人靠上下文不会读错，**机器靠句法就会选错**。
CosyVoice 选了右边，于是把停顿给了「撕」。

**所以：这不是 bug，是文案要改。**
而且 CosyVoice 是**确定性**的（同文本同 seed 逐样本一致），
`--tts-only` 重跑一百遍还是同一句读法，白烧时间。

同批还查出第二处（老板没提，但确实错了）：

> 「每一百克蛋白质给到 **15.4克**，脂肪压到2.8克。」
> 读成「给到 **15.4克脂肪**｜压到2.8克」

因为「15.4克脂肪」是合法短语，模型把「脂肪」当成了「给到」的宾语。
**产品核心数据被听错，比断句难听严重得多。**

## 二、前置闸门：`tts_break_risk.py`（配音前跑，零成本）

```bash
python3 scripts/tts_break_risk.py --phrases <工程>/phrases.txt
```

退出码：`0` 干净／`5` 有 R1、R2 必须改／`6` 只有 R3 提示。

| 规则 | 触发条件 | 为什么会被读错 | 改法 |
|---|---|---|---|
| **R1** | 分句以**单字动词**收尾（撕／掰／切／压／抹／泡／冲／拆／拧／开…） | 模型极易在单字动词后断 | 换双字动词，或在动词前加修饰语（「撕」→「随手撕」） |
| **R2** | 分句是「**动词+数量词**」，下一分句以**副词**开头（都／也／就／才／还／又／全／再） | 数量词会被下一分句抢去当主语 | 让下一分句不再是「数量词+副词」结构：`都不用开火` → `连火都不用开` |
| **R3**（提示） | 分句以「**数字+物质计量单位**」收尾（克/毫克/千焦/毫升/升/斤/两/卡），下分句开头是名词 | 名词被吸成前者的定语：`15.4克` + `脂肪` = `15.4克脂肪` | 逗号后加一个**不能与数量词组合**的虚词（`而`），或把两个数据拆成两句 |

**R3 只认物质计量单位，不认个体量词**（天/个/包/箱/片）。
因为「15.4克脂肪」组装得成，「30天袋子」组装不成 —— 限定后假报清零。

## 三、后置闸门：`tts_hearback.py`（合成完跑，抓漏网的）

```bash
python3 scripts/tts_hearback.py --wav <工程>/audio/vo.wav --phrases <工程>/phrases.txt
```

做法：拿 **whisper 对 vo.wav 做独立听写**（不喂我们的文本，避免自证），
把 whisper 的分段边界映射回原文下标，再分两级判定。

退出码：`0` 通过／`5` 有 A 级（必须重配）／`6` 只有 B 级／`2` 环境不可用。

| 级别 | 判据 | 含义 |
|---|---|---|
| **A 级** | 分段边界落在「距最近标点 **1～3 字**」的位置 | 短句被从中间切断，听感就是「撕｜两片」。必须改文案重配 |
| **B 级** | 边界距标点 ≥4 字 | 多为句首主谓之间的自然韵律，通常可接受，只报告 |
| **B 级** | 标点处 whisper 没有边界 | 漏气口，一口气读过去，只报告 |

依赖：
- `~/.workbuddy/models/whisper.cpp/build/bin/whisper-cli`
- `~/.workbuddy/models/whisper.cpp/models/ggml-base.bin`

两者缺一就退出码 2，提示「改为人工听一遍全片再交付」，不阻断流程。

### ★ 实现里踩过的两个坑（改脚本前必读）

1. **数字坐标系必须统一**。原文 `15.4` 是 4 个字符，转成「十五点四」是 5 个字。
   若标点位置按原字符数算、正文按转换后算，两套坐标混用会**错位 1 位**，
   逗号处的正确边界会被误判成「距标点 2 字」，整天报假警。
   `load_phrases()` 里逐字符走一遍、数字串整体转中文，同步累加下标才对。
2. **行末也算标点边界**。`phrases` 一行一句，行与行的分界就是句号。
   不把它算进去，每两句之间都会被误判成「距标点 N 字的误停」（实测 16 处假报）。

## 四、改这类句子的通用思路

按效果排序：

1. **让后一分句不能再吞掉前面那个词** —— 最稳
   - `都不～` → `连～都不`（`都不用开火动锅` → `连火都不用开`）
   - 逗号后加 `而`（`15.4克，脂肪…` → `15.4克，而脂肪…`）
2. **给单字动词配个搭档** —— `撕两片` → `随手撕两片`
3. **把两个数据拆成两句** —— 用句号断开。注意这会多一个语音句，
   要同步改 `shot_map` 与 `.split.json`（**代价最大，最后才用**）

改完必须：`tts_break_risk.py` 过 → `--tts-only` 重配 → `tts_hearback.py` 过 → 再渲染。
**三道都过才算修完，不许只看一眼「好像对了」。**

## 五、这次没做的事

`fx` 层（飞入大卡、数字滚动、圆环卡）**本片未启用**。
fx 三件套缺一不可：`.fx.json` 侧车 + `.kw.json` + `config.fx.enabled: true`。
本片只有 `.kw.json`（音效）和 `config.keywords`（字幕高亮），没有 `.fx.json`，
所以画面上**没有大字**，只有字幕里的词变金黄 + 逐词音效。

`pipeline_run.py` 每次都会打这条警告，**不是 bug，是没配**：

```
⚠️⚠️ fx 层未启用（fx.enabled=None）：重点字/数字动效一律不出（底片 keywords=[] 是设计如此，不是 bug）
```

要大字必须另开一次、按 fx 三件套补齐，并且过 Remotion（本机 8GB 内存，按铁律不跑重渲染）。
**交付时不许把「字幕变色」说成「大字重点字」** —— 2026-11-11 就是这样在发布文案里写错的。

## 三、★第三道闸（2026-11-13 立）：**一行里不许有句中逗号** —— 逐字时间戳会在第一个逗号处截断

> 起因：给爱兰纯肌酸 261113_2 写 phrases.txt 时，为了保留口语气口，把两句合成一行
> 「19块9买三百克肌酸，听着不太像真的」。语音本身没问题，**但 `vo.words.json` 里
> 只剩前半句 10 个字**，后半句的逐字时间戳全丢了 —— 下游字幕会整片错位。

**实测证据（2026-11-13，cosyvoice-v3.5-plus / rate 1.1）**：

| 合成文本 | 音频时长 | 返回词数 | 返回内容 |
|---|---|---|---|
| `19块9买三百克肌酸` | 1.75s | 10 | 完整 |
| `听着不太像真的` | 1.31s | 7 | 完整 |
| `19块9买三百克肌酸，听着不太像真的` | **3.10s ≈ 1.75+1.31** | **10** | **只到第一个逗号** |
| `19块9买三百克肌酸。听着不太像真的。` | 2.75s | 全 | 完整 |

**结论：音频是完整的（时长等于两句之和），丢的是 `words` 数组。**
服务端按标点把文本内部拆成多个 sentence 事件，
`cloud_cosyvoice_ws.synth()` 只保留了 `len(words)` 最大的那一条（`if len(w) >= len(best_words)`），
所以句中一有逗号，后半句的时间戳就被丢掉。**重跑没用**（合成确定性），只能改写法。

**硬规则（写文案阶段就要守）**：

1. `phrases.txt` **一行一个语块，行内不许出现 `，、：`**；语块末尾该带 `。` 就带 `。`。
2. 每个语块的有效字 ≥ 6（`cut_phrases` 的 `min_len`）——否则会被并到下一句，
   而合并时 `pipeline_run.py` 第 129 行会把句号改回逗号，**又把逗号带回来**。
   所以「太便宜了。」这种 4 字句要并进上句写成「一罐就能喝一百天太便宜了。」
3. 验收：合成完立刻查 `vo.words.json` 的 `normalized_text` 长度是否等于全文
   （去标点后）。少一个字符就是踩了这个坑。
   ```bash
   python3 - <<'PY'
   import json
   d=json.load(open("<工程>/audio/vo.words.json"))
   w="".join(x["text"] for x in d["words"])
   print("词数", len(w), "| 归一化文本长度", len(d["normalized_text"]))
   PY
   ```
   两者应基本相等（数字会展开成汉字导致词数略多，但**归一化文本必须覆盖到最后一个语块**）。

**代价说明**：这么写出来句间停顿会比原稿的逗号气口长（约 370ms），
但换到的是逐字字幕对得准。**要气口就得自己切行，不能让一行里夹逗号。**
