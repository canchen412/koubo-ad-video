# 封面帧 · 定式（2026-10-29 老板拍板「以后封面就这样做」· 2026-10-30 两次修订）

> 一句话：**封面取自「视频池抽帧」或「分镜底图」（首选无产品的动作帧），取 3:4 竖幅，居中放在 16:9 中间，做视频第 0 帧停留 0.5 秒。**
> 判据来源：261029 VORSE 姜黄素（老板「这张封面就做得很好」）+ 261030 诺特烟酰胺两次打回（「不要用产品当封面」「尽量不要用产品出现在封面里」）。

## 一、四条铁律

| # | 铁律 | 为什么 |
|---|---|---|
| 0 | **封面主体必须是 IP 人物本人**；**首选画面里没有产品的纯人物瞬间**，产品当手持道具是次选，**禁止用「只有瓶子/罐子」的产品图做封面** | 2026-10-30 老板两次原话：①「**封面不能就用那个 21 金维他这个瓶子，封面要用小绿人，小绿人最有冲击力的一幅**」②「**这个封面尽量不要用产品出现在封面里，可以截取底图视频里面的一帧具有冲击力的画面，也可以截取图片里面一帧的画面**」。纯产品瓶＝货架图，信息流里没有对视感、没有肌肉张力；带产品的图就算人再猛，第一眼也容易被读成「又一条广告」，**纯人物动作帧（出拳、力竭、腾空、对视）才是第一眼抓人的构图** |
| 0b | **相邻两条片的封面不许撞脸**：同一 IP、同一产品，第二条起必须换素材类型（上一条用产品怼镜头 → 这条就用力竭/出拳的动作帧） | 2026-10-30 老板原话：「**最好不要和之前的封面相重复，重复过多**」。同一个号连着两条一模一样的构图，等于把老观众劝退、把新观众当成重复投放 |
| 1 | **封面取自「分镜底图」或「视频素材池抽帧」**（`分镜图库/<IP>/视频素材/*.mp4`），**不许从成片截帧** | 成片截图会把**字幕、98% 圆环、重点字/更便宜**这些东西一起带进去。261029 第一版就是从成片 20.9s 截的，画面底部压着「配料表每粒 300mg」，96% 的封面都是这样废掉的。视频池抽的帧是干净的原始画面，且天然无字幕 |
| 2 | **只取 3:4 竖幅**，且**几何居中**放在 16:9 画布中间。两侧默认**同源图模糊压暗 + 正弦缓入消融**（§3.1，2026-11-04 起为默认）；`make_cover_frame.py` 输出的是**纯黑版**，只在环境无 PIL 时兜底 | 抖音按 3:4 居中裁 16:9 时，裁切宽 = 画布高 × 0.75 = 810、起点 x = 555，**正好命中这块竖图**，一点黑边都不带进去。偏一寸就会带黑边或切掉主体。**为什么不用纯黑**：两侧各 555px 大黑块在信息流里像「贴了张图」，虚化带让整帧完整、观感高级，且消融带仍在裁切区之外（清晰区 366~1554 覆盖裁切区 555~1365） |
| 2b | **产品只要出现在封面里，瓶身/罐身的水平中心必须压在画面中线 x=960**（差 5% 就是歪的） | 2026-11-01 老板原话：「**只要产品出现在封面里，产品一定要居中对齐**」。261101 赛霸那条瓶心在 1055（偏右 95px≈5%），第一眼读成「没对齐」。**量法**：白瓶用「mx>170 且 (mx−mn)<40」做列投影求 bbox，**搜索必须限制在中区 x∈[500,1100]**——两侧白色护腕会把 bbox 撑到 550~1150、中心算成 850，全是假的。**落位**：移动景观取窗 `x0 = 瓶心 − 窗宽/2`，让瓶心落到取窗中心；**不许平移主体、不许抠图补胸口背景**去凑（会切手/露接缝）。取窗被 3:4 锁死切手时，**宁可加宽清晰区**（261101 实测 810 → 1188），两侧用同源图 `blur40 + brightness0.65` + 90px 正弦缓入渐变消融 |
| 3 | **必须是视频第 0 帧**，停留 **0.5s（15 帧 @30fps）** | 平台抓首帧做封面；0.5s 是为了兜住「有的端取 0.5s 附近那一帧」的差异。1 帧（0.034s）太薄，容易被跳过 |

## 二、选哪张底图

### 2.0 先选来源：视频池抽帧 > 图片底图

| 顺序 | 来源 | 什么时候用 |
|---|---|---|
| **首选** | `分镜图库/<IP>/视频素材/*.mp4` 抽一帧 | **默认走这条**。视频素材本身就是「动态瞬间」，抽出来的帧天然带动作张力，而且**全部无产品**，正合铁律 0。小绿人池子里力竭、出拳光爆、腾空、碎镜对视这些帧，比任何静态产品图都猛 |
| 次选 | `分镜图库/<IP>/<产品>/图片/*.png` 静态底图 | 视频池里实在没有贴题的动作时才退回来，且优先挑**人物占满竖幅、产品在手里不在正中间**的那张 |

抽帧要点（2026-10-30 实测）：
- 素材普遍 1280×720。3:4 窗口 = **540×720**（高度撑满、宽度 = 高 × 0.75），放大 **1.5×** 到 810×1080。
- 1.5× 放大务必补 `unsharp=5:5:0.35`，否则皮肤纹理发糊；出图后**缩到 216 宽再目视一遍**（模拟信息流缩略图），小图能看清动作才算过关。
- **同一段素材是持续运镜的**（推近 / 拉远），要逐个时间点试，别只用 2.5s。261030 力竭那条 0.6s 是全身、4.4s 已经糊成大特写，只有 2.5s 是「半身 + 握杠铃 + 直视镜头」的甜点。
- 横向只能挪窗口位置：`crop=540:720:X:0`，X 从 `(1280−540)/2 = 370` 起，主体偏一侧时按 120~150px 步进试（261030 出拳帧最终用 X=500，把出拳手臂和火花都收进来了）。

### 2.1 再打分

> **第 0 关（一票否决）：画面里必须站着 IP 人物**。只有产品瓶/罐/盒、或只有一只手托着瓶的，
> 直接淘汰，不参与打分。2026-10-30 老板把「收尾_巨型瓶金色爆发」当封面的版本打回就是这个原因。

1. **有动作或有对视**（出拳 / 发力 / 力竭抬头直视 > 正面站立 > 侧身 > 背影）
2. **动作肢体的末端不能被裁掉**——出拳的手、举起的瓶，3:4 窗口必须把「打到哪儿」收进来；裁在手腕上等于动作废了
3. **主体在竖向中轴上**，左右各留一点余量（3:4 只有 810 宽，主体一偏就被切）
4. **背景是暗调或纯色**——两侧黑边与背景同色系时过渡自然，亮背景会像贴了块白板。暗场动作帧（出拳光爆、力竭）在缩略图里明暗对比最抓眼
5. **画面里除了人（和手持产品）没有别的信息**（避开带字幕/带问号警示/带对比双人的图）
6. 若画面里出现产品，瓶身品牌字**不能被切**；但**不要为了保住瓶身字牺牲动作**——这一条优先级低于 1、2

## 三、裁切怎么算（别凭感觉拖）

底图三种常见尺寸，3:4 窗口按「高度撑满、宽度 = 高 × 0.75」算：

| 底图 | 3:4 窗口 | 放大到 810×1080 |
|---|---|---|
| 1536×1024（1.5） | 768×1024 | 1.055× |
| 1536×864（1.78） | **648×864** | **1.250×**（放大 >1.1 时补 `unsharp`） |
| 2730×1536（1.78） | 1152×1536 | 0.703×（缩，不锐化） |
| **1280×720（视频帧，1.78）** | **540×720** | **1.500×（必须补 `unsharp=5:5:0.35`）** |

- **横向只能选窗口位置，纵向不能移**（高度已经撑满）。所以选窗前必须看主体是否居中被切。
- 3:4 窗口 x 的取法：默认几何居中 `(W − w) / 2`；主体偏一侧时手动微调，但**每次只挪 60~80px 逐步试**，三档并排出图目视选（261029 试了 x=360/444/520，444 最对称）。
- 放大超过 1.1 倍时加 `unsharp=5:5:0.5:5:5:0`，补偿清晰度；底图有效宽度不足 810 的（如 648 宽），直接告诉老板「再大要回图库出高分辨率版」。

### 3.1 画面里有产品时：先算瓶心，再定取窗（2026-11-01 新增）

3:4 窗口只有 810 宽，**产品居中和「人物双手完整」经常打架**（261101 赛霸：源图 1536×864，瓶心 844 = 偏右 76 源像素；右手到 1330、左手从 380 起，跨度 950 源像素 > 648 取窗）。三条路别走错：

| 做法 | 结果 |
|---|---|
| ✅ **加宽清晰区**（把「3:4 竖幅」换成「宽竖幅」） | 清晰区 1188 → 取窗 950×864（仍 1.25×），`x0 = 瓶心 844 − 475 = 369`，瓶心落 `460+(844−369)×1.25 = 960` ✓；左右手全在窗内 |
| ❌ 3:4 死守 648 取窗 + 右移取窗 | 瓶心确实到 960，但左手被丢 76 源像素＝**整只手掌出框**，断手 |
| ❌ 抠瓶平移 + 镜像补胸口 | 接缝必露（胸口中缝/光影方向反），且要动 1080 帧里的一帧，风险不成比例 |

**加宽后的合成式（261101 定稿参数）**：

```python
bg  = src.resize((1920,1080)).filter(GaussianBlur(40)); bg = brightness(bg, 0.65)
CARD_W, SCALE = 1188, 1.25; win_w = 950
x0  = int(round(瓶心 - win_w/2))                      # 369
fg  = src.crop((x0,0,x0+win_w,864)).resize((CARD_W,1080))
px  = (1920-CARD_W)//2                                # 366
# 90px 正弦缓入渐变，左右消融（去掉硬边画框感）
mask[:, px:px+FADE] = sin(t*pi/2)**2 ; mask[:, px+CARD_W-FADE:px+CARD_W] = 反过来
out = bg*(1-mask) + fg*mask
```

- 为什么不用纯黑边：261101 起改「同源图模糊压暗 + 渐变消融」，1680 宽的虚化带照样满足「3:4 居中裁不带黑边」（裁切区间 555~1365 全在核心清晰区 458~1466 内），观感比纯黑高级。
- **量完必复核**：出图后重新跑一次瓶心检测（中区限制），标点与 960 差 >10px 就重算 `x0`；再与正片第 1 帧比对，`abs mean diff < 2` 才算接缝无跳变。

### 3.2 ★★2026-11-13 硬坑：`cover_frame` 必须喂**原始底图**，不许喂已经裁好的 3:4 竖图

**症状**：成片第 0 帧里小绿人被横向挤扁（头变宽、腿变短、身体像被压扁的贴纸）。261113 液体钙实测。

**根因**：`build_cover_blur` 旧版的清晰窗宽是按「画布高 × 990/1080」算的固定值——源图是 1536×1024 时窗口 939 宽（等比），
但如果你塞进去的是 `cover-design` 已经裁好的 **1080×1440 竖图**，需要的窗口是 `1440×990/1080 = 1320` 宽，
比源图还宽 ⇒ 旧代码把窗口 `min` 成源宽 1080，再 `resize` 到 990×1080 ⇒ **横向压缩 8%**，人立刻变形。

**正解**：`cover_frame` 一律给**分镜底图原图**（1536×1024 / 2730×1536 这类宽幅），**不要给 `封面_3x4.jpg`**。
`cover_rect` 在 blur 模式下也不要用——它是纯黑模式（`cover_fill: black`）的裁切窗，写错了直接裁出错图。

```jsonc
"cover_frame": "/Volumes/素材库/广告视频/分镜图库/小绿人/液体钙/21金维他/图片/产品_怀抱六瓶21金维他液体钙_中景.png",
"cover_fill": "blur",          // 不要写 cover_rect
"cover_dur": 0.9
```

**代码已修**（2026-11-13）：`make_cover_frame.py::build_cover_blur` 改成「一律等比缩放到画布高，比 card 宽就居中裁、比 card 窄就整幅居中贴」，
任何源图都不再做非等比缩放。但**规矩不变**：喂原始底图，清晰度最高、3:4 裁切区最贴。

**复核动作**：出片后抽第 4 帧（0.13s）量人物头顶到脚底的像素高度 / 肩宽比，与源图比对误差 >3% 就是被拉伸了。

## 四、怎么做（三种入口，任选）

### ⓪ 首选：从视频池抽一帧当底图

```bash
V="/Volumes/素材库/广告视频/分镜图库/小绿人/视频素材"
# 1) 抽帧存成工程内的底图（不要留在 /tmp，重出时要用）
ffmpeg -v error -y -ss 2.5 -i "$V/展示_暗场出拳能量爆炸_全景_AI动态.mp4" \
  -frames:v 1 -vf "unsharp=5:5:0.35" 封面/底图_出拳光爆_261030.png
# 2) 走标准流程（--rect 按 540:720:X:0 给）
$PY $SK/scripts/make_cover_frame.py \
  --src 封面/底图_出拳光爆_261030.png --rect 540:720:500:0 \
  --video v1/render/final30.mp4 --out-dir 封面 --apply
```

**选帧方法**：先把候选素材按 0.8 / 2.5 / 4.2s 各抽一帧拼成接触表，一次看完再决定；
挑中后再对那一条按 0.6 / 1.5 / 2.5 / 3.4 / 4.4s 细抽五帧，选「主体最饱满且不糊」的那一帧。

### ① 脚本（推荐，出图 + 贴帧一步到位）

```bash
PY=/Users/yourname/.workbuddy/binaries/python/envs/default/bin/python
SK=~/.workbuddy/skills/koubo-ad-video

# 只出封面图（blur 填充是默认，取窗自动居中）
$PY $SK/scripts/make_cover_frame.py \
  --src "$图库/产品_双手捧VORSE姜黄素罐_中景.png" --out-dir ./封面

# 指定取窗左边界（blur 模式按「3:4宽+180」= 990 宽取窗，用 --x0 挪窗口）
$PY $SK/scripts/make_cover_frame.py \
  --src 封面/底图_v1.png --x0 285 --out-dir ./封面

# 回退纯黑边（底图极暗、模糊版会糊成一片时才用）
$PY $SK/scripts/make_cover_frame.py \
  --src 封面/底图_v1.png --x0 285 --fill black --out-dir ./封面

# 直接贴到成片（产出 <成片名>_cover.mp4，交付用这个）
$PY $SK/scripts/make_cover_frame.py \
  --src 封面/底图_v1.png --x0 285 \
  --video 成片.mp4 --out-dir ./封面 --apply
```

产出：`封面_3x4.png/.jpg`（810×1080）、`封面_16x9_居中.png`（1920×1080）、`封面_参数.txt`（裁切参数 + 亮度自检，**抄进发布文案**）。

★ **2026-11-04 起 `--fill blur` 已内置**（原来是临时脚本 `make_cover_blur.py`，已废弃）：
清晰窗 990×1080、中间 810 是平台 3:4 裁切区（555~1365）必须纯清晰、两侧各 90px sin² 消融、
背景 = 整图 LANCZOS + `GaussianBlur(40)` + 亮度 0.65。
**同参数重跑 sha 不变**（261104 实测 `5fd04bba…` 逐字节一致）——封面可复现，不必留工程。

★ `--rect w:h:x:y` 是 black 模式的显式裁切窗；blur 模式用 `--x0` 给左边界，别把 540 宽硬塞。

### ② 出片时自动带（pipeline）

config 里加两项，第 6.5 步自动贴：

```json
"cover_frame": "/绝対路径/产品_双手捧VORSE姜黄素罐_中景.png",
"cover_rect": "648:864:444:0",      // 可不写 → 自动 3:4 居中
"cover_dur": 0.5                     // 默认 0.5s
```

## 九、卷播片实战三条（2026-11-04 烟酰胺三条一批，老板打回「封面不对」）

### ① `"cover": false` 是绕过闸门的后门，写一次就永久没封面 —— **禁写**

`pipeline_run.py` 的硬闸条件是
`banner and not cover_frame and cover is not False and not allow_no_cover`，
所以只要 config 里写了 `"cover": false` 或 `"allow_no_cover": true`，闸门**静默放行**，
第 0 帧就是卡牌墙，平台抓首帧当封面 → 3:4 竖裁正好切在卡与卡接缝上。

本轮就是这么漏的：出片日志里一句「卷播片不贴静态封面」被当成正常行为，
其实是自己写的 `cover: false` 把它关掉了。**判据**：
出片后抽第 0 帧，若看到的是卡片堆＋钩子字幕而不是一张完整的人像竖图 ⇒ 立刻回查 config。

### ② `deliver_check` 的粒子项会因为参照版没封面而假红 44%

`--dust-ref` 传的是 `render/final_nodust.mp4`（无粒子版），它**不含 0.5s 封面段**；
而 `--final` 含封面 ⇒ 两版差 0.5s 时间轴，逐帧差分把整帧封面算成「亮斑」，
报「亮斑占比 44.30%（应 0.5~25%）」。

**修法**：给参照版**贴同一张封面**再比对——

```python
import sys; sys.path.insert(0,"/Users/yourname/.workbuddy/skills/koubo-ad-video/scripts")
from make_cover_frame import apply_to_video
apply_to_video("v1/render/final_nodust.mp4", "封面/封面_16x9.png", 0.5, "封面/v1/nodust_cover.mp4")
```

对齐后实测亮斑回到 16.98% / 24.91% / 20.06% 全绿。
**也就是说：任何给成片加过前置段的操作，参照版都必须同样加一遍，否则所有基于「逐帧差分」的检查项全部失真。**

### ③ 抽帧时刻：推近运镜取最早、抬头镜取头顶有留白那一帧

同一段素材按 5 个时刻各裁一版 3:4 并排比，本轮两个反例：

- `开场_聚光灯蓄力缓推` 是**持续推近**：2.5s 时膝盖以下已出框，取 **0.6s** 才全身。
- `举铁_力竭瘫坐杠铃前` 是**越来越近**：2.54s 头顶贴到画面上沿，取 **1.50s** 头顶留白。
  （4.4s 已经是脸怼屏，直接淘汰。）

判据：**头顶到上沿要有留白、动作末端不出框**。3:4 窗口高度撑满、纵向不能移，
所以只能靠**换时刻**解决，不能靠调窗口 y。

### ④ 同批多片：封面底图必须来自不同视频，且尽量避开本片已用镜头

本轮三条：力竭（v1）/ 出拳光爆（v2）/ 聚光灯蓄力（v3），三个不同视频池素材；
v2 片内第 6 镜是力竭、v3 片内第 6 镜是出拳 ⇒ 封面各自避开本片已出现的那一段。
缩略图（216px 宽）并排目视确认「蹲姿 / 宽站出拳 / 正面站定」三态一眼可辨。

### ⑤ ★★ 选底图的**第一步**是「抽源帧看脚掌在不在画面内」（2026-11-04 剑盾蛋白吐司实撞）

§九③ 写了「头顶要有留白、动作末端不出框」，但它管的是**同一素材换时刻**。有一种情况换时刻也救不回来：

**仰拍构图的素材，人物脚本来就在源画面之外。** 本轮先选了 `科普_高蛋白餐盘山降到正面_全身_AI动态`
（2.0s），构图是「小绿人站在巨型餐盘前、镜头仰拍」，画面冲击力很强——出图后脚踝以下全被切，

## 十一、封面在流水线里「整条静默丢失」（2026-11-10 剑盾吐司三版实撞）

**老板原话**：「封面要加到成片里面去，我发视频直接就不用调了。」
查交付的三条标准版——第 0 帧全是黑的，**一张封面都没进片**。

### 根因：不是没做，是做完被下一个环节丢了

pipeline 6.5 贴完封面，产物是 `render/final_cov.mp4`，紧接着 `os.replace` 改名成 `final.mp4`。
这一步在文件被占用 / 权限受限时会抛 `PermissionError`，代码只打一行 ⚠️ 就继续往下走。
于是 `final.mp4` 还是**没封面的底片**，而 `fx_cards.py` 只认 `final_dust.mp4` / `final.mp4`，
叠完卡交出去的 `final_num.mp4` 自然就是黑首帧。

时间线实证（同一工程同一时刻）：

| 文件 | 时长 | 说明 |
|---|---|---|
| `final_main_enc.mp4` | 46.37s | 正片编码 |
| `cover_clip.mp4` | 0.50s | 封面静帧 |
| `final_cov.mp4` | 46.89s | 0.50 + 46.37，**含封面** |
| `final.mp4` | 46.37s | 无封面（rename 没成功） |
| `final_num.mp4` | 46.37s | 叠卡输出 = 交付件 = 无封面 |

### 修法（已改进脚本）

1. `fx_cards.py` 取源候选改为 `final_dust` > `final_cov` > `final`，后两者按 **mtime 取新**。
   固定顺序有个坑：重跑过 pipeline 却没清旧 `final_cov.mp4` 时，会叠在**上一次的旧片子**上。
2. 封面驻留 0.5s → **0.9s**：给平台/人工拖封面留出选帧窗口（0.5s 只有 15 帧）。
   默认值同时改到 `fx_cards.py` 的 `shift`（时间轴偏移）——两处必须一致，否则卡片整体错位。
3. **不要给封面段加 fade out**：一加，封面末尾就是暗帧，平台抽到那一帧封面对比度塌掉；
   而且 `check_cover.py` 判据②「第 0 帧 ≈ 第 26 帧」直接判失败（实测 diff 52.78）。
   封面必须**全亮驻留、硬切**接正片；正片自带的黑场淡入负责「亮→暗→亮」，那 0.2s 是常规开场。

### 双闸门（两条各管一段，都要跑）

内容闸门用**去均值 NCC**（对整体亮度差不敏感，封面淡出后的帧也认得出）。
实测贴对了 0.999–1.000，没贴 0.107。三条片子封面各不同，没有这道闸时贴串了根本查不出来。

## 十二、封面小片的**帧数口径**：`round(dur*30) + 2`（2026-11-10 换镜1 重渲时定死）

`check_cover.py` 的两条判据是挨着的两帧，**中间只隔 1 帧，没有容错**：

| 判据 | 取帧 | 要求 |
|---|---|---|
| ② 封面停住 | 第 `round(dur*30)-1` 帧（0.9s ⇒ 第 26 帧） | 与第 0 帧 diff **< 1.0** |
| ③ 正片进来 | 第 `round(dur*30)` 帧（0.9s ⇒ 第 27 帧） | 与第 0 帧 diff **> 3.0** |

⇒ 成片里封面必须**正好** `round(dur*30)` 帧静止。少 1 帧挂②（实测 diff 12.69），多 1 帧挂③
（diff 0.02，「封面贴太长」）。**可用区间只有 1 帧。**

坑在于 `concat -c copy` 会吃掉封面小片尾部 1 帧，而 `-t` 卡时长在边界上还会让末帧变异。
所以**不许用 `-t` 控制小片帧数**，要用 `-frames:v` 精确给：

```python
_nfr = int(round(_cdur * 30)) + 2       # 0.9s ⇒ 29 帧 → 拼完正好 0..26 静止、27 切正片
sh([FF, "-y","-v","error",
    "-loop","1","-framerate","30","-i", cover_169_png,
    "-f","lavfi","-t", f"{_nfr/30:.4f}", "-i", "anullsrc=r=44100:cl=stereo",
    "-frames:v", str(_nfr), ...])
```

⚠️ **`-frames:v` 必须写在所有 `-i` 之后**。写在两个 `-i` 之间会被当成下一个输入的输入选项，
报 `Option frames:v cannot be applied to input url anullsrc` —— 和 `-vf` 踩的是同一个坑。

**验收口径只能用 `select` 抽帧**，不能用 `-f rawvideo` 数帧：rawvideo 拿到的帧序比 `select` 的
`n` 早 1 帧，同一份成片 rawvideo 说「第 26 帧静止」、`select` 说「第 26 帧已变」，会把人带沟里。

**另**：`fx_cards.py` 的 `shift` 读的是 `cfg_<版本>.json` 的 `cover_dur`，**不是** `<版本>/config.json`。
两处不一致时卡片整体早/晚 `cover_dur` 差（本次 0.5 vs 0.9 ⇒ 全片卡片早 0.4s），而且日志不会报错。
