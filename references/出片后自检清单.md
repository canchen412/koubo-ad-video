```bash
python3 <SKILL>/scripts/deliver_check.py --final 成片.mp4 \
  --banner rem3d/out/banner_x.mp4 \
  --hero-fg rem3d/public/cards_x/hero_fg.png --hero-cfg brand_x.json \
  --base-fx render/base_fx.mp4 --base render/out_base.mp4 \
  --fx-decl 文案.fx.json --fx-spec rem3d/src/fx_spec_x.json \
  --cover render/cover_169.png \
  --cards "1260,20,506,488:卡名@32.0"
```

| # | 检查项 | 判定线 | 适用条件 |
|---|---|---|---|
| 6 | 体积 | 折算 53 秒后 20~40MB | 全部 |
| 7 | 视频码率 | 3~6 Mbps | 全部 |
| 8 | faststart | 容器首个 box 必须是 `moov` | 全部 |
| 9 | 真峰值 | ≤ −0.5 dBTP | 全部 |
| 10 | 响度 | −11~−13 LUFS | 全部 |
| 11 | 封面首帧 | 与 `--cover` 底图像素差 < 6 | 全部 |
| 12 | 卷播主图大字出现 | 字块内金色 > 1.5% | 带卷播 |
| 13 | **大字被人物遮挡**（3D 景深） | 人物区 ÷ 空白区 金色密度 **< 0.8** | 带卷播＋分层图 |

### 25. 数字动效不得与重点字重合，也不得被当成人物主体 【新增】

| 子项 | 判定 | 方法 |
|---|---|---|
| 25a 不与重点字重合 | 数字动效 bbox ∩ 大字字块 bbox ≤ 数字动效面积的 **10%** | 读 `fx_spec_*.json` 落位 vs `hero_label_size/top` 推算的字块 |
| 25b 不落在人物本体上 | 数字动效区域落在 `hero_fg.png` alpha>0.5 的像素 ≤ **15%** | 掩膜相交 |
| 25c **不被当成人物主体** | 人物掩膜**必须**取 `hero_fg.png` 的 alpha，**禁止**用亮度/肤色/金色阈值反推 | 代码级锁死 |

**为什么 25c 必须单列**：第 13 条靠"人物区字密度 ÷ 空白区"判遮挡。若人物掩膜是颜色反推来的，
金色数字动效会被算进"人物区" ⇒ 分母虚高 ⇒ **一个字没被遮也会判成被遮**，13 条直接失效。
2026-11-01 本条片的掩膜走的是 alpha，是安全的；写成规则是防止以后有人图省事改回颜色法。

**适用**：有 `fx` 数字动效的片子。本片（建模照镜派）产品段无数字动效 → `N/A`。

## 30｜头顶安全区（人物镜必查 · 2026-11-02 老板「人物头都裁到外面去了」后立）

**查什么**：每一格画面的最上方，绿色人形的头顶是不是完整的圆弧，而不是被上边缘切成一条直线。

**怎么查**（一条命令，出图人眼看）—— **必须查成片，不是查素材**：

```bash
python3 <SKILL>/scripts/head_room_sheet.py \
  --final 工程/render/final.mp4 --bounds 工程/audio/shot_bounds.json --out /tmp/hr.png
```

出「每镜顶部 30% 条带拼图」，**红线＝该画面的第一条像素**。逐格看：头顶碰到红线、或被红线截断 → 该镜重做。

**判定**：任何一格头顶贴红线 = 不合格。素材留白目标 **≥12%**，因为成片每镜过热 zoompan
（wide 1.10 每边裁 4.5% / mid 3.4% / close 2%）＋微晃 1~2%，素材留 6% 进成片只剩 1%。

> **★★ 素材 PASS ≠ 成片 PASS（2026-11-02 第二次事故，老板第二次抓同一件事）**
> 镜15「走廊啃蛋白棒」的素材我看过条带、判了「有留白」，成片里头顶照样切平。
> 两个原因叠在一起：
> ① 条带只取顶部 18% 且缩到 720 宽 —— 头顶和天花板灰度接近时看不清，所以把 BAND_PCT 提到 30%、OUT_W 提到 900；
> ② **检查对象错了**：zoompan 会再吃掉 3.4%，素材上够、成片上不一定够。所以入口一律走 `--final`。
> 教训一句话：**要验的是观众看到的画面，不是硬盘里的 PNG。**

**原图已经无余量可裁时，只能重生成**（⛔ 别再调 y0）：
镜15 原图人物从头顶 149px 一直到脚 1010px，跨度 861px，而 16:9 裁框正好 864px ——
要同时保住头和脚就一寸不剩。这种「全身走路 / 全身站立」构图，1024 原图里天然没有可裁空间。
重生成 prompt 的关键不是「留白 12%」而是 **`REFRAME ONLY — pull back and widen`** + 人物高度写死
（`he occupies no more than 62% of the frame height`）+ 脚底也要留 8%，两头一起锁。

**本轮实锤**（仁和烟酰胺）：
- 镜13 原图头顶就被切平 —— 生成时 prompt 只写「底部 25% 留净空」，模型把人物整体上推；
- 镜01 头顶 139px → 成片 0px —— 1024 原图按底部对齐裁（y0=160）；
- 镜16 头顶 110px → 成片 9px —— 居中裁（y0=80）；
- **镜15 素材正常、成片切平** —— 原图无余量（见上），只能重生成；顺手把 `motion` 改 `static`。
- 修完后成片实测：镜01 13.0%、镜13 35%、镜15 23%、镜16 3.5%（static 后稳定）。

**素材可用段怎么定**（槽位比可用段长时）：**逐帧**量头顶绿区到上沿的距离，取「连续 ≥5%」的**最长前缀**，
不许抽几帧目视估。镜15 实测 f0 13.1% → f32 5.1% → f34 4.4% → f40 0.3%（出画），
故只能用 f0–f33（1.133s），再用 `minterpolate` 补帧慢放 1.48× 补满 1.68s 槽位
（命令与 `-r 30` 的坑见 SKILL.md「Wan 2.7 会把『推近 X%』放大成 3–6 倍」节）。

**⛔ 不要试图用脚本自动判**：绿 mask / 边缘背景差分 / 中轴限定三种算法对同一张贴顶图给出
0% / 32% / 35% 三个数，且把头顶完整的镜17、镜19 误判成贴顶。绿光、墙色、镜面倒影都会污染判据。
**这条只能人眼看条带图** —— 别为了「自动化」再造一个误报闸门。

**特写镜是例外**：镜17（掌心两粒白片）、镜13 这类特写，人物只到胸口或手臂，头顶本就不在画面内 ——
判据不是「头顶留白」而是「被切处是在表达重点之外」。特写里被切的若是手臂/下巴，属正常构图。

### 29. 卷播/封面接缝不得有「碎片镜」（<0.30s 一闪而过）🔒 【新增 2026-11-02】

**老板原话**：「卷播过后又闪了一下，千万不要闪，找出问题出来，那闪那一下是什么图片加进去了，把它删掉。」
—— 261102 两条片都中了，肉眼是「闪一下」，查出来是 **2 帧**。

**根因**：卷播（banner）切点 = banner 时长 + tail，比下一镜起点**晚**了。
被挤的那一镜窗口还剩一丁点，成片里就成了 2~3 帧的残尾。它既不是黑帧、也不是卡帧，
**qc_all 四项全绿也照样存在** —— 现有所有质检都抓不到，必须单独量。

**判据**（脚本自动）：

```bash
python3 <SKILL>/scripts/check_banner_handoff.py --video 成片.mp4
# 默认只看 0~8s 接缝区；任意相邻切点间隔 < 0.30s ⇒ 碎片 ⇒ exit 1
```

261102 实测：旧版 `0.50 → 4.604 → 4.671 → 9.33`，中间 4.604→4.671 只有 **0.067s（2 帧）**
= 「开场_聚光灯蓄力缓推_全身」的残尾。剪掉后 `0.50 → 4.667 → 9.333`，干净。

**⚠️ 为什么默认只扫前 8 秒**：全片扫必误报。科普段/情绪段的**镜内闪光、爆点、粒子**同样被
scene 检测成切点（261102 实测 14.5~16.6s 连出 12 个 0.167s 假切点）。窗口外的只提示、不判废。

**修法（不重渲整片，音画不错位）**：把 `[s, e]` 剪掉，**用前一镜末帧 freeze 补同等时长**，
音频整条 copy 不动 ⇒ 时长不变、音画同步不变。freeze 的是卷播末帧（本就定格），视觉无感。
> 261102 用过：`trim=0:4.604 + tpad=stop_mode=clone:stop_duration=0.067` 再接 `trim=4.671`，
> 音频 `-c:a copy`；改完 36.70s 一帧不差。

**根治**：卷播切点必须 ≤ 下一镜起点。算完 banner 后拿 `audio/shot_bounds.json` 对一遍，
切点落在哪一镜中间，就把 banner 从尾部裁到那个镜的起点。

### 31. 任何一个产出文件都不许超 40MB —— 底片也算 🔒 【新增 2026-11-02】

**老板原话**：「这个成片的产物又到了 156 兆 B 了，这个不行这个还是太大了，我之前不是说过
产出的要控制在 40 兆以内吗？」

**被判废的不是交付片，是中间底片**：261102 交付片只有 20.4MiB（5.04Mbps），完全合格；
但 `s1/render/out_base.mp4` 因为渲染器写死 `h264_videotoolbox -q:v 72`，跑到
**40.7Mbps / 156MB**，而下游交付编码本来就只有 5Mbps —— 底片超额 8 倍，纯粹白占磁盘，
人一眼看到的却是这个 156MB 的巨物，直接判「产出太大」。

| 文件 | 之前的参数 | 实测 | 现在的参数 | 实测 |
|---|---|---|---|---|
| `out_base.mp4`（底片） | `-q:v 72` | 40.7Mbps / **156MB** | `master_q` 默认 **58** | 7.7Mbps / **29.4MB** |
| `final.mp4`（拼封面后） | CRF19 | 28.7MB | 不变 | 28.7MB |
| `final_fx.mp4`（交付） | CRF19 | 21.3MB | 不变 | 21.3MB |

**画质代价**：q:v 58 重编码对原底片聚合 **Y-PSNR 55.94 dB**（单帧均值 42.9 / 最低 32.1，
低值出现在运动帧），肉眼无差；底片 7.7Mbps 仍高于交付 5.04Mbps，留有储备。

**规矩**：
1. 交付片：`deliver_check.py` 第 1 项已按时长折算卡 16~45MB/53s，保持。
2. **底片/中间产物同样 ≤40MB**。渲染器现在会在超标时打 ⚠️ 并给出改法；
   要更高储备就在 config 写 `"master_q": 62`（≈10.3Mbps / 39.2MB，仍不破线）。
3. 片长变长（>40s）时底片自然变大，**必须回头把 master_q 往下降到 55 左右**，
   不能因为「片子长了」就默认超线合理。

### 32. 产品段必须有「详情卡 + 能数清的滚动数字」🔒 【新增 2026-11-02】

**老板原话**：「后面的产品端，它的详情卡片怎么没出来，还有数字滚动它怎么都没出来呢，把它都做上。」

**但人眼看不见就等于没做**。

| 项 | 定式 | 验收判据 |
|---|---|---|
| 数字滚动 | 0.06 起滚、**0.44 落定**（13 帧） | 逐帧抽 5 帧，数字必须出现 ≥3 个不同值 |
| 音效落点 | 落定 = t0 + 0.50 | `SFX` 的 t 必须等于该值，早 0.1s 就成「先响后到」 |
| 详情卡 | `DetailCard`（金标题 + 白标签/金数值两栏 + 灰脚注） | 产品段每一条卖点句至少一张；抽帧确认卡内文字与口播一致 |
