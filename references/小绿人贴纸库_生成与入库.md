## 〇、三条铁律（先看这个，违反必返工）

1. **一张图最多 2 个人，且只能是窄姿态。** 想省积分塞 8~9 个是反的：
   极简版成片 1920×1080，贴纸实际渲染高 **峰值 940px**（C 区主位）/ 讲解位 740~800，
   素材内容高 1000 —— **每格高必须 ≥900px**。
   塞 9 个（3×3）每格只有 450px，要 2.1× 上采样，边缘线条变软、1~2px 抠像误差放大成 4px 白边；更致命的是两个绿色人物挨着就**切不开**。
   | 排法 | 每人像素 | 放大倍率 | 结论 |
   |---|---|---|---|
   | 3×3 九个 | 450px | 2.1× | ❌ |
   | 2×2 四个 | 676px | 1.39× | ⚠ 勉强 |
   | **左右两格** | 900px | 1.04× | ✅ 等同原生 |
2. **宽姿态一律单出。** 运动/道具类宽高比 1.2~1.6（你库里冲刺跑 1519×1032=1.47、杠铃过头 922×1032=0.89），
   在 1536×1024 里放两个每格只剩 768 宽，**胳膊和器械必被裁**。
   只有宽高比 ≤0.8 的收拢姿态（情绪/身体状态/看读/手势）能拼。
3. **小绿人没有嘴、没有眉、没有鼻，只有两只纯黑椭圆眼。** 提示词里出现「微笑」「皱眉」「生气」这类词，
   模型会本能地给它画五官，**IP 当场崩掉**。情绪只能靠**体态 + 头部倾斜 + 眼形**表达
   （眼睛压扁=得意、缩成窄缝=怀疑、睁到最大=惊讶、头埋进膝盖=崩溃）。

D 身体状态 10（拼 5）、E 看读 8（拼 4）、F 数字手势 6（拼 3）。★ 第一批 34 张。

### 1.1 豆包实测的四个偏差（写提示词时就要防）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **人物只占画面高度 61%（约 630px）**，抠出来要 1.49× 上采样 | 模型自作主张留大片空白 | 提示词钉死「身高占满画面 **88%**，上下各只留 6%」，并加一句「人物要画大、不许在上方留大片空白」 |
| 2 | **出的是橄榄绿 RGB(70,94,61)**，老库是鲜草绿 RGB(54,127,66)，并排像两个演员 | 生图模型的绿色偏黄偏灰 | ① 提示词写「**鲜亮的草绿色**，接近 RGB 60,170,85，不要橄榄绿/军绿/黄绿」；② 回来仍要跑 `tone_match.py` 兜底 |
| 3 | **同一张两格姿态画成几乎一样**（G5 左右都画成推手） | 两个 prompt 差异不够大 | 同一张的两个姿态**必须拉开**（一个后仰一个下蹲、一个单手一个双手），否则等于白花一张 |
| 4 | 右下角带生成器水印 | 平台固定打点 | 提示词要求**右下角留空**，别让水印压在人物上 |

## 二、切图 + 调色 + 入库（五步，命令可直接抄）

```bash
cd "/Volumes/素材库/广告视频/分镜图库/小绿人/_抠图库"

# 1. 豆包出的图先丢进 _待入库_<YYMMDD>/，名字带组号：G1_得意认可_1536x1024.png

# 2. 双人图切两格（自动按垂直投影找中间最宽空白带切开）
#    两半各自走 色键 → refine 净边 → 归一化到内容高 1000 / 脚底 24px
python3 _tools/split_pair.py --src _待入库_261103/G1_得意认可_1536x1024.png \
        --prefix 反应_叉腰得意 --out _待入库_261103/切图_试验
#    蹲姿右格必须加 --suffix2 _贴地（否则蹲着的小人按站高拉伸，跟站着一样大）

# 3. 调色对齐老库（不调就是两个演员）
python3 _tools/tone_match.py --src 切图_试验/xxx_净边.png \
        --dst 切图_试验/调色/xxx_净边.png --ref 角色/反应_摊手耸肩_全身_净边.png

# 4. 入库 + 规格校验 + 写索引（改名规则见 §三）
python3 _tools/import_reactions.py

# 5. 出联系表给人验收
python3 _tools/make_contact_sheet.py --glob "反应_*_净边.png" \
        --out _预览/联系表_反应12_261103.jpg --title "反应库"
```

**色键强度**：`split_pair.py --thresh`，默认 1.4。实测 1.0 的白毛边残留比 1.4 多一倍；
但 1.0→1.6 之间肉眼差别只在 1~2px，**别在这上面反复调参**，真实场景是漫画墙深底，不是纯黑底。

**渲染器已自动优先加载 `_净边.png`**，所以入库件带 `_净边` 后缀即可直接给 plan 用。

## 三、命名：`大类_具体画面_景别[_净边].png`

切图工具的临时名（`_1` `_2` 序号）**一律不入库**。名字必须能看出姿态，否则半年后按名检索会拿错。

| `反应_推手慌张_2_全身` | `反应_双手交叉挡_全身` | 原名与 1 号重名，检索分不开 |

## 四、验收口径（原库判据在切图产物上会全线误报）

⚠️ 原库「前景占比 >45% 记为背景残留」**对切图贴纸全部失效**：切图会裁到人物外框，
人自然占满画布，12 个里 6 个被误报。改用四条（`import_reactions.py` 已内置）：

| 检查 | 合格区间 | 12 个实测 |
|---|---|---|
| 内容高 | 985~1005（规格 1000） | 全部 1000 |
| 脚底基线距底 | 14~42 px（规格 24） | 全部 24 |
| 左右透明边 | 各 ≥6 px | 通过 |
| **第二大连通块 / 主体** | **≤5%** | 全部单一连通块 |

最后一条最关键：**单一连通块 = 切图时没把旁边那个人的胳膊带进来**。
没有 scipy 也能做（`import_reactions.py` 里 4 倍下采样 + BFS，758×1032 秒级）。

**目视验收另看三条**：有没有长出五官 / 两人之间有没有粘连 / 水印有没有压到人。

```

├─ 角色/                56 个贴纸（本轮 44→56，反应类 15 个）
├─ 物品/                目前只有胶囊，食物/器械/水杯全缺
├─ _源图/261103/        9 张源图存档（3 张单人竖图 + 6 张 G 组双人拼图）
│                       —— 重生成要花积分，双人拼图以后还能重切，所以源图不删
├─ _预览/               联系表
├─ _tools/
│   ├─ gen_sprite_spec.py     生图表生成器（改 CATS 重跑即刷新 html+md）
│   ├─ split_pair.py          双人拼图切两格
│   ├─ tone_match.py          色温对齐老库
│   ├─ import_reactions.py    入库 + 四条规格校验 + 写索引
│   ├─ make_contact_sheet.py  任意 glob 出深底联系表（用途小字从索引读）
│   └─ finalize_261103.py     定稿清理（源图存档 / 重复件按 sha1 删 / 中间产物清）
├─ _索引_反应_261103.json     带 use（用途）与 group（G1左 这类来源组号）
└─ _README.md                 命名规范 + 第八节「反应类专项」含 12 个文件→接哪句话
```

**成本口径**：双人拼图约 15 分/张 → 7.5 分/个（单出约 15 分/个）。
省下的积分不多（60 分只占余额 0.7%），**真正值钱的是同图两人天然同一个人、同一光照、同一画风**。
