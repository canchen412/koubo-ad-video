# 镜内快推（push）—— 只在这两种情况下用

> 2026-11-02 老板定，B 款落地。原话：
> 「当物品或者人物比较小的时候可以这样做，因为如果太大的话，它放大了之后它就溢出屏幕了。
> 如果物体很小、瓶子很小，那么是近图的话，他这样做就把瓶子放大，就看起来更有动感一点。
> 如果是只有小绿人的话，然后他做出比较惊恐惊讶的表情，突然一下放大到他的头部也行。
> **只有这两种情况可以做这个快速运镜，其他的都还是做原来的效果。**」

问题背景：产品段全是静图，原来的 `zoom_in` 整镜只推 1.02→1.10，实测 60% 的帧 Δ<1.0，
观感就是「会动的照片」。快推是给这些静图补一次真正的镜头运动。

---

## 一、只有两档，别自己加第三档

| 档 | 用在什么镜 | 目标点 |
|---|---|---|
| `push_product` | 小绿人和产品**同框**，产品在画面里**小** | 瓶身（或标签）中心 |
| `push_face` | **只有**小绿人，且表情是**惊讶/惊恐** | 头部 |

`push_face` 必须人工确认表情 —— 脚本认不出表情，看到「只有小绿人」不等于可以推。
普通表情的大头推近是「无意义的放大」，不批。

其余一切镜（纯产品特写、人物占满、多主体、分屏、远景空镜）**一律保持原来的 `zoom_in` /
`zoom_out` / `pan_l` / `pan_r`**。

---

## 二、三条否决判据（`push_subject_check.py` 自动跑）

| 判据 | 阈值 | 为什么 |
|---|---|---|
| 主体太大 | 占画宽 > **26%** | 推 2 倍就顶满，就是老板说的「溢出屏幕」 |
| 主体太小 | 占画宽 < **10%** | 推到清晰度上限也只占 ~20%，推了等于没推 |
| 推完高度爆 | 占画面高度 × z > **96%** | 超过就顶满/裁穿瓶盖，产品看不清 |
| 景别太近 | 文件名含 近景/特写/大头/脸部/半身 | 源图有效细节不够，再推就是糊 |

**高度这条才是真瓶颈，别只卡宽度。** 2026-11-02 同一镜踩了三次：

| 试的倍数 | 结果 |
|---|---|
| 1.75× | 瓶盖裁掉一半，**底部「运动营养食品 耐力类 / 净含量 72g」整行被裁没** |
| 1.48× | 瓶盖仍被裁，小绿人的头也被裁出画 |
| 1.34× | 实测瓶身 y 已是 0~1025（满高），瓶盖贴边看不见 |
| **1.28×** | 瓶盖完整、净含量完整、小绿人完整，0.55s 内放大 28%，推进感还在 ✅ |

原因：产品图的瓶子是**竖长条**，宽度只占 14.1% 很富裕，**高度却占 74.8%**，
所以 `z 上限 = 96% / 74.8% ≈ 1.28` 才是真天花板。只按宽度会算出 1.75 这种明显错的答案，
**必须以高度算出来的为准**。`push_subject_check.py` 两个都算、取小的。

清晰度上限（源图宽度决定）：1536 → 2.20×，1920~2047 → 2.60×，≥2048 → 2.80×。

**为什么 26% 这条最要紧**：静图出图一般 1536×864，推到 1.75× 后取窗只剩 878×494 再上采样到
1920×1080。主体再大一点，既糊又裁穿。所以「主体小」不是审美偏好，是硬约束。

## 三、参数（B 款，老板 2026-11-02 选定）

```
前段停留 hold = 1.1s   （只做 1.02→1.08 的轻缓推，让人和产品先同框停一拍）
猛推   dur  = 0.55s   （1.08 → z，ease 指数 2.2，快起快落）
落定   呼吸 = 0.006*sin(on/9)
终点   z    = **以闸门算出来的为准**（镜 07 是 1.28，别照抄 1.75）
```

时长自适应（短镜不能挤爆）：`hold ≤ 镜长×0.45`，`dur ≤ 镜长×0.30`。
镜长 2.04s 时实际 hold≈0.92 / dur=0.55，落定留 0.57s。

C 款（0.4s 推到 2.15×，落标签）**已被否**：2.15× 在原图上采样过头，边缘偏软。
B 款最初试的 1.75× 也被否：幅度不是问题，**高度溢出**才是问题（见上表）。

`shot_map.json` / `phrases` 写法：

```json
"motion": "push",
"push": {"to": [0.6035, 0.5208], "z": 1.28, "hold": 1.1, "dur": 0.55}
```

- `to` 是**归一化**坐标（0~1），与出图尺寸无关 —— 换 1920 或 1536 的图不用改
- 目标点必须落在主体中心；取景框边界由 `min(max(cx,0),iw-iw/zoom)` 自动夹紧
- 目标点太靠边时（需 z < 1/(2·dist_to_edge)），zoompan 会夹框 ⇒ 推歪，闸门会报「目标点太靠边」

## 四、开工顺序

```bash
# 1. 先测能不能推（不给 --z 就按清晰度上限评估最坏情况）
python3 ~/.workbuddy/skills/koubo-ad-video/scripts/push_subject_check.py \
    --shot-map shot_map.json --workdir .        # 不给 --z 会自动算安全上限

# 2. 只给通过的镜写 motion=push，其余不动
# 3. 重渲底片 → 拼封面 → 叠 fx
```

**⚠️ 改 `shot_map.json` 不等于生效**：`build_ad_video.py` 读的是运行时 `s1/config.json` 的
`phrases[]`。两处都要改（这也是 2026-11-02 `dup_shot_check.py` 报 KeyError 的同源坑）。

## 五、案例：赛霸 261102

| 镜 | 内容 | 主体占画宽 | 推完宽/高 | 结论 |
|---|---|---|---|---|
| 07 | 小绿人 + 单瓶并排 | 14.1% | 18.9% / 96% | ✅ 推 1.28×（瓶高 74.8% 是瓶颈） |
| 13 | 双瓶并立 | 15.6%（单瓶） | — | ❌ 两瓶合看 36.6% 太大，不推 |
| 12 | 瓶身散落片剂近景 | 14.0% | 25% / 143% | ❌ 近景 + 高度裁穿 |
| 06 | 柜子塞满无标签瓶 | 29.8% | — | ❌ 太大（且是他品/无标签瓶，更不能推上去） |
| 09/11/15 | 光带 / 空柜一罐 / 收尾递产品 | 6~9% | ~19% | ❌ 太小，推了没感觉 |

一行结论：**一条片子里能开快推的镜通常只有 1 个**，就是「人 + 产品首次同框」那一镜。
不要为了动感多开，多开必然踩到「太大」或「太小」。
