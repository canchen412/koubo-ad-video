# 产品段动效卡：黑底金数字卡 + 详情卡（2026-11-02 姜黄素三版定稿）

> 唯一入口脚本：`scripts/fx_cards.py`
> 本文只讲**怎么用 + 为什么这么写**；风格口径见 `自建fx动效层_PIL逐帧.md`。

## 一、什么时候用

口播里出现**可数的数字**（剂量 / 纯度 / 规格 / 数量 / 价格）或**可列的成分**时，产品段必须上这两种卡：

| 卡型 | 触发内容 | 例子 |
|---|---|---|
| 数字卡 `NumCard` | 单个硬数字 | 300 mg / 98 % / 2 瓶 |
| 详情卡 `DetailCard` | 一组成分或规格 | 姜黄素 300mg・纯度 98%・黑胡椒提取物・肉桂 |

**两条不许犯**：
1. 详情卡内容只能写**口播真说过的词与数**，不许自己加（加了就是虚假宣传素材）。
2. 详情卡**不许复述数字卡的副标题** —— 两张卡同一句话，观感就是重复。

## 二、跑法

```bash
python scripts/fx_cards.py --work <工程目录> v1 v2 v3
# 输入：<工程>/<版>/render/final.mp4（底片）+ <版>/phrases.txt + <版>/audio/shot_bounds.json
# 输出：<工程>/<版>/render/final_num.mp4（叠卡后成片）
```

内容全在 `<工程>/fx_spec.json`，**脚本本身不含任何品牌文案**：

```json
{
  "v1": {
    "num":    [["<镜句关键词>", "300", "mg", "<副标题>"]],
    "detail": [["<镜句关键词>", "<标题>", [["<标签>","<数值>"]], "<脚注>"]]
  }
}
```

`镜句关键词` = 该版 `phrases.txt` 里那一句的**原话片段**，唯一命中即可；找不到脚本直接 `SystemExit`，不静默跳过（跳过＝这张卡悄悄没了）。

## 三、时间轴（脚本已固化，不用手调）

| 阶段 | 数字卡 | 详情卡 |
|---|---|---|
| 滑入 | 0.32s（从右下淡入，缓出） | 0.30s |
| 主体 | 滚数 0.62s（easeOutQuint，逐位老虎机） | 展开 0.90s（金短线 → 逐行淡入 → 脚注） |
| 回弹 | 0.16s 放大 6.5% 再回落 | — |
| 停留 | 到 `dur-0.24` | 同 |
| 淡出 | 0.24s | 同 |

- `dur` 默认按句子时长给（数字卡 `min(2.4, max(1.9, 句长+shift))`，详情卡固定 2.3s）。
- `shift = cfg.cover_dur`：成片前面拼了封面/卷播，`shot_bounds` 是按**配音**算的，必须先加 `shift` 才对得上画面。
- 详情卡起点再往后错 0.95s，避免和同句的数字卡同屏并排。

## 四、落位（自动，别手填坐标）

`pick_pos(mask, cw, ch)`：**60px 步长滑窗**扫全画面，取「绿色主体占比」最低点。

- 绿色掩膜：`(g>70) & (g>r+22) & (g>b+22)`
- 字幕带（底部 128px）不落卡
- 已占位区在掩膜里置 `True`，第二张卡自动避开第一张
- 同分时轻微偏好靠边（左上/右上）

**判据**：数字卡 0.000~0.037、详情卡 0.014~0.152 可接受；**>0.20 必须换落点或换镜**。
★ 别用稀疏格点（`for y in (132,260,400,540)` 那种）—— 避不开人物时只能选"最不差"，实测会落到 0.22~0.28，肉眼就是卡压在胸肌上。

## 五、三个必须知道的技术坑（每个都导致"卡看不见"或"数字错"）

### 5.1 overlay 没对齐时间轴 ⇒ 一张卡都看不见

卡片 mov 只有 2 秒，主视频 23 秒才用它。不偏移的话，卡在 2 秒时就 EOF，`eof_action` 默认 `repeat` 停在**最后一帧＝淡出后的全透明**。

```bash
[{i}:v]setpts=PTS-STARTPTS+{start}/TB,format=rgba[fx{i}]
[{cur}][fx{i}]overlay=x=..:y=..:format=auto:shortest=0:eof_action=pass:enable='between(t,{start},{end})'[v{i}]
```

两个参数缺一不可：`setpts` 对齐起点、`eof_action=pass` 播完透传主画面。

### 5.2 老虎机窗口偏移符号写反 ⇒ 落定值差 10−target

错：`y_off = -(pos*row_h) % (10*row_h)` → 300 落成 700。
对：落定时 `pos = float(tgt)`，`y_off = int(pos*row_h) % (10*row_h)`。
且数字条要做 **11 行**（末尾再补一个 0）当进窗缓冲，否则滚到 9.x 会露出透明底。

### 5.3 滑入位移被卡片画布裁掉 ⇒ 卡片缺一块、数字只剩半截

滑入 `dx/dy` 最大 90/46，若 mov 画布就是卡片尺寸，位移部分直接被裁。
修法：画布 `+120 × +80` 余量，卡最终落 (0,0)，overlay 时 mov 左上角对准落位点。

## 六、验收（抽帧硬标准，不许目视糊过）

1. **落定值必须等于文案数字** —— 每张卡抽「落定后」一帧，读出卡上的数字，`300 / 98 / 2` 逐张核对。滚不对就是 5.2 那个坑。
2. **卡片完整** —— 四个边都看得见圆角，没有直切边。
3. **不压绿** —— 抽落位帧算绿占比，>0.20 不合格。
4. **不重叠** —— 同屏两张卡不许叠；同句两张必须错开落点与时段。
5. **中文不出豆腐块** —— 数值栏含 CJK 时用中文字体（见 5.4）。
6. **不糊** —— 卡片是矢量重绘（PIL 逐帧），任何尺寸都不该糊；糊了说明被缩放，查 `write_clip` 的 `MX/MY`。

### 5.4 数值栏字体：DIN 没有 CJK 字形

`DetailCard` 的数值可能写「配着」「收着」「没少」这类中文。统一用 DIN 会渲成 **□□**。
按内容选：

```python
font = self.f_v if all(ord(c) < 128 for c in val) else self.f_v_cn
```

## 八、落位/时长手填（`fx_cards.py` 的 spec 扩展项）

自动落位靠「绿占比」挑空白，**在暗调、灰雾、主体占满的画面里会失效**（绿占比恒为 0，
pick_pos 落到最近的边角，常见结果是卡片压住底部字幕或压住产品瓶上的品牌字）。这时手填。

`spec[v]["num"]` 每项：

```
[关键词, 大数字, 单位, 副标题, [x, y]?, 时长s?]
```

- 第 5 项 `[x, y]`：强制坐标（1920×1080 画布左上角）。给了就跳过自动选位。
- 第 6 项 `时长`：缺省按句长算 `min(2.4, max(1.9, 句长+封面偏移))`。

`spec[v]["detail"]` 每项同理，坐标是第 5 项（`[x, y]`）。

**什么时候必须手填时长**：卡片跨到下一镜、而下一镜画面很满（产品特写、双瓶全身）
无处可躲时。数字卡读得完最短约 1.1s；再短就该考虑删卡——信息若和同句字幕完全重复，
卡片只是视觉噪音。

实测（2026-11-05 VORSE 261105）：
- 「2瓶」卡放 (1480,320) 自动时长 1.9s → 27.72–29.62s，跨进下一镜 0.67s，
  稳稳压在产品瓶的 `VORSE` / `Curcumin` 大字上；下一镜主体占满、四角皆非空。
- 改 `[1480, 320, 1.15]` → 27.72–28.87s，收在本镜内（本镜 27.57–28.95），问题消失。
- 另注：卡片入场动画的头 0.2s 数字是滑入中的半截（易被误读成「0瓶」），验收要抽
  **落定后**的帧，不要抽入场帧。

## 九、手绘红圈（2026-11-10 老板定，蛋白吐司标准版三版首发）

> 原话：「说到好多少多少克的时候，一定要用卡片上面有个红圈圈一下。」

**判据**：卡片上出现**克数／分数／百分比**这类"多少"的量，那个数就必须被红圈圈住。
只圈「数值 + 单位」，不圈标签；副标题和脚注不圈。

### 9.1 开法（spec 位置参数）

| 卡型 | 第几项 | 写法 | 缺省 |
|---|---|---|---|
| 数字卡 `num` | 第 7 项 | `true` / `false` | **缺省开**（数字卡的存在意义就是把那个数指出来） |
| 详情卡 `detail` | 第 6 项 | `[0]` / `[0,1]`（行号，0 基） | 缺省 `[]` 不圈 |

```json
"num":    [["一百克里蛋白质有15.4克", "15.4", "g", "每100克蛋白质"]],
"detail": [["反式脂肪酸是0", "另外三项",
            [["脂肪","2.8 g"],["反式脂肪酸","0"],["蔗糖添加","0"]],
            "数据以包装营养成分表为准", null, [0]]]
```

`ring_rows` 给了超出范围的行号会 `SystemExit`，不静默忽略。

### 9.2 为什么不用 `ImageDraw.arc`

arc 是**正圆弧 + 等宽**，一眼看出是软件画的。手绘圈有三个特征，缺一个就假：

1. **首尾叠一点** —— 绕 **1.10 圈**（不是 1.00），起笔与收笔必然交叠；
2. **半径不规则** —— 三组不同频率正弦叠加（3/5/9 阶，振幅 5.2%/2.8%/1.6%），
   比 `random` 稳：帧间连续不跳，且不依赖随机种子；
3. **笔迹两头细中间粗** —— `0.55 + 0.45*sin(π*u)`。

再加 **−4° 倾斜**（手画不会端端正正）。★倾斜超过 6°，圈左端会翘到字上去。

实现：超采样 2 倍、逐点画圆头小点连成笔迹，最后 `LANCZOS` 缩回，边缘不锯齿。

### 9.3 时间轴

| 卡型 | 起笔 | 描完 |
|---|---|---|
| 数字卡 | `slide0.32 + roll0.62 + bounce0.16 + 0.02` = **1.12s** | +0.34s |
| 详情卡 | `slide0.30 + rev0.90 + 0.02` = **1.22s**，多行再各错 0.20s | +0.34s |

- 早画＝在圈空气（数字还在滚），所以必须等**落定 + 回弹收住**。
- 卡太短压不出圈：`rdur < 0.12` 直接跳过并打印 `⚠️ 红圈来不及画`，**不画半个圈**。

### 9.4 三个坑（都导致"圈歪"或"圈不到"）

**坑 1 — 墨迹顶边就是 `num_top`，别再减一次偏移。**
数字条是按「行内垂直居中」`paste` 上去的，`paste_y` 已经减过 `(row_h-num_h)/2`。
再减一次 ⇒ 圈整体上移 22px，圈的下沿横穿数字，看着像划杠不像圈。

**坑 2 — 卡宽要把圈算进去。**
圈右端必须离卡边 ≥30px，否则圈贴着卡边，像被裁掉半张。
`self.cw = max(block_w + PAD*2, ring_x1 + 30)` 反推。

**坑 3 — 数字卡必须支持小数点。**
旧版 `frame()` 对每个字符 `int(ch)`，`15.4` 里的 `.` 直接 `ValueError`；
且按 `digit_w` 等宽推进会把小数点撑成一个数字宽。
现改为**逐字符预排位置**：小数点按自身墨迹宽 + 窄间距（3px，普通字符 8px）。

### 9.5 验收（硬标准）

1. **抽帧时机**：卡片起点 + **1.5s 之后**再抽。抽到滚动中会读成 `00.0` / `37.6`，
   抽到描线中会看到"只画了一半的圈" —— 这两个都不是 bug，是抽早了。
2. 圈必须**闭合**，且完整包住数值 + 单位（不是只圈住前两位）。
3. 圈不许压到数字笔画（倾斜角过大时左端会翘上去）。
4. 卡宽 ≥ 圈右端 + 30px。
