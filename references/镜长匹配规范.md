# 镜长匹配规范 —— 别让画面"杵着"等口播（2026-11-13 定）

> 老板原话：「前面的视频很短，但是那句话还没说完这个视频就放完了，最后一帧一直在那里杵着，这个问题你给个方案怎么解决。」
>
> 这份规范就是那个方案。**排完 shot_map 必须先过 `shot_fit_audit.py`，exit 0 才允许渲染。**

## 一、先破一个误解

不是「先生成分镜再配音」导致的问题。流程一直是 **TTS 先跑 → 拿 `durations.json` 逐句精确时长 → 再排镜**。

真问题是排镜时两个盲区：

1. **只看内容对不对，不看素材够不够长** ⇒ 短素材撑长句，渲染时靠 `tpad=stop_mode=clone` 冻末帧硬垫（`build_ad_video.py` 的 `_vpad` 分支）。
2. **只看素材有没有运镜，不看这段画面在不在动** ⇒ 静图推近幅度太小（3.87s 只推 5%），字幕一稳定整段帧差分掉到 0.07，肉眼等于静帧。

三条片实测：7 处冻帧，最大一处 **1.85 秒**，位置就在片子最开头（v1 镜1：句子 3.87s，素材 2.02s）。

## 二、五条硬规则

### 规则 1：单镜时长上限 = 素材长 ÷ 0.55

| 素材长 | 能撑的最长镜 |
|---|---|
| 2.02s（Wan 2.7 默认 2 秒母版）| **3.67s** |
| 3.02s | 5.49s |
| 5.09s | 9.25s |
| 静图 | 不限 |

- 镜长 ≤ 素材长 → 直接 trim 截短，零损伤。
- 素材长 < 镜长 ≤ 素材长/0.55 → 慢放 `speed = 素材长 ÷ 镜长`（0.55–1.0x），`shot_fit_audit.py --apply` 自动生成变速副本。
- 镜长 > 素材长/0.55 → **不许硬撑**，必须走下面三条之一：
  - **拆句**：`文案.split.json` 给该段拆成两镜，重跑 `--tts-only`
  - **换长素材**：挑 ≥ 镜长×0.55 的
  - **换静图**：静图长度任意，Ken Burns 推近撑住

### 规则 2：短镜（<1.2s）要当心转场吃画面

转场 `dur=0.34s`，前后各吃一次 ⇒ 1.0s 的镜实际可见不到四成。短镜尽量：
- 不给它开 `no_zoom`（短镜没时间积蓄动作，必须靠推近补运动感）
- 或干脆不让它成为独立镜（并进相邻镜）

### 规则 3：静图推近不许太轻

`build_ad_video.py` 景别档位：`wide.zrange=0.110 / mid.zrange=0.075 / close.zrange=0.030`（2026-11-13 上调，原 0.090/0.050）。
短镜自动按缺口加幅：`zr *= 1.0 + (1.6 - dur) * 0.55`（1.6s 以下生效）。
imgvid 镜推近 `1.04 + 0.13*ease`（原 `1.06 + 0.08`），1.0s 以下加到 0.20。

判据：**帧间平均差分 < 0.6 且持续 ≥ 0.35s = 画面死了**。正常运动片是 3–6。

### 规则 4：开场第一镜必须用视频（2026-11-13 老板追加）

> 原话：「开头尽量用视频」。

镜1 是全片唯一必须抓人的位置，静图靠 Ken Burns 推近撑 2 秒以上，观感仍然是「一张照片贴上去」。

- **禁止**镜1 用静图。`shot_fit_audit.py` 已做硬闸：镜1 是静图直接 `exit 2`。
- 首句太长（>3.5s）撑不住视频时，**先在 `文案.split.json` 拆句**，再给每一半各配视频 —— 不要为了方便直接退回静图。
- 确无合适视频，才加 `--allow-img-open` 显式放行。
- 开场运动量单独看：**镜1 的帧差分要 >0.6**（落在 0.10–0.45 的「缓推区间」就算不合格）。
  实测 v2 首镜素材仅 2.02s、被迫慢放 0.61x、还带 `no_zoom` ⇒ 差分 0.58，
  三帧对比几乎同一张脸。修法是**去掉 `no_zoom` 让推近接管**，不是换素材（脸/头部素材全库最长只有 2.02s）。

### 规则 5：节奏目标 —— 平均 2.6~2.8s，每镜 ≥1.75s

> 原话：「现在确实节奏更稳更慢了，我还想稍微再快那么一点点」。

两版实测对照（改了三次才找到平衡点）：

| 版本 | v1/v2/v3 镜数 | 平均镜长 | 问题 |
|---|---|---|---|
| 初版 | 14/12/12 | 2.2s | 太碎：短镜被 0.34s 转场吃掉，整段退化成上一镜静帧 |
| 二版 | 9/8/9 | 3.3s | 太慢：观感「稳定但拖」 |
| **定版** | **11/9/10** | **2.5~2.7s** | 目标区间 |

- 快手：`文案.split.json` 只拆「跨两个分句」的长句（一个逗号一组），拆完每半必须 ≥1.75s。
- 减速：长句配长素材或换静图，不要硬拆成 1.7s 以下的碎镜。
- 闸门会在平均镜长 >3.2s 时给「慢警告」，>1.75s 是硬下限。
- 拆句时注意：**镜数 = 语音句数 + 拆分增数**，拆完 `len(shot_map)` 必须等于新镜数，否则渲染报
  `shot_map N 项 ≠ 内容镜 M`。

## 三、闸门用法（两步，缺一不可）

```bash
# 第 1 步：排完 shot_map 立刻体检（不花钱、几秒出结果）
python3 scripts/shot_fit_audit.py \
    --shot-map <工程>/shot_map.json \
    --bounds   <工程>/<name>/audio/shot_bounds.json

# 有 SLOW 判定时要回写慢放副本（改 src 指向变速副本）
python3 scripts/shot_fit_audit.py --shot-map ... --bounds ... --apply
# → 产出 <工程>/shot_map.fit.json，喂渲染时用这个
```

退出码：`0` 全过 ｜ `2` 有镜超窗或残留冻帧 >0.10s ｜ `4` 输入问题。
**exit 2 一律不许渲染**，先按提示拆句/换素材。

### 还有一条硬对齐：shot_map 条数 == 句子条数

实测三条片全部都少一镜（v1 13 镜对 14 句、v2/v3 11 镜对 12 句），最后一句没有镜头 ⇒ 画面延续上一镜 = 尾巴定格 1.2–2.5 秒。
**排完先数一遍**：`len(shot_map) == len(phrases_shots.txt 行数)`。

## 四、成片后必查

```bash
# 逐帧运动量扫描（找"死段"）：差分 <0.6 且 ≥0.35s 的区段全部列出来
python3 - <<'PY'
import subprocess, numpy as np
src = "成片.mp4"; w, h = 160, 90
p = subprocess.run(["ffmpeg","-v","error","-i",src,"-vf",f"scale={w}:{h}",
                    "-pix_fmt","gray","-f","rawvideo","-"], capture_output=True)
a = np.frombuffer(p.stdout, np.uint8); n = len(a)//(w*h)
d = np.abs(np.diff(a[:n*w*h].reshape(n,h,w).astype(np.float32), axis=0)).mean(axis=(1,2))
print("全片均值", round(float(d.mean()),2), "｜ 中位", round(float(np.median(d)),2))
PY
```

判读：
- 开头 0–0.9s 差分为 0 → 封面帧，正常。
- 中段差分 <0.6 的段超过 1 秒 → 必须回查该镜素材长度与推近。

## 五、踩过的坑

| 现象 | 真因 | 修法 |
|---|---|---|
| 一句话说完画面还在，最后一帧不动 | 素材短于镜长，`tpad clone` 冻末帧 | 慢放 或 拆句 或 换静图 |
| **首镜冲击完就静止 3 秒多** | `punch` 动效后段每帧只 `+0.004` 且封顶 `zmin+amp*0.75`，实测 0.43s 就到顶 | 已修：剩余幅度摊到整镜（`+amp*0.55*min((on-10)/(n-10),1)`） |
| 静图镜看着像照片贴上去 | Ken Burns 只推 5%，且 `ease=out` 末尾导数趋零 ⇒ 最后 20% 几乎不动 | zrange 提到 0.120/0.150；`ease` 默认改 `linear` |
| 短镜整段像静帧，素材本身明明在动 | `no_zoom: true` + 从素材 0s 起播，吃到 AI 的「起手静止」 | ← 1.6s 以下强制推近（已改）；`pick_active_window.py` 挑活跃段 |
| 片尾定住两秒 | shot_map 少一镜，最后一句没画面 | 条数对齐 |
| 慢放后画面顿挫 | speed<0.85 时帧数不足 | 30fps 复制帧可接受；<0.55 直接不许用 |

### ⚠️ 试过但走不通的：短镜硬切

想让 <1.2s 的短镜绕开转场（0.34s 前后各吃一次），试过把相邻切点的 `_T` 压到 1 帧。
**结果 fx 模式的 xfade 链直接崩**：视频流只剩 5.17s（音频 32.37s），报 `视频流被截断`。
原因：`_start_pad`、`_off`、`_want` 三处闭合依赖 T 的连续值，T 退化到 1 帧后累积帧号对不上。
**结论：别从 T 下手。** 正确做法是排镜阶段就别产生 <1.2s 的镜——
`splsplit` 少拆、或把短句并进相邻镜，让每镜 ≥1.75s。三条片改完后最短镜 1.75s，转场占比 <40%，观感正常。

### 帧差分判据怎么读（重要，别误判）

| 差分 | 含义 |
|---|---|
| **0.00–0.03** | 真冻帧（tpad clone）——必须消除 |
| 0.10–0.45 | 缓慢推近（Ken Burns）——正常，1080p 上肉眼可见，缩略图测不出来 |
| 0.6–2 | 中速运动 |
| 3 以上 | 强运动（AI 动态素材、转场） |

早期拿 0.6 当门限去卡"缓推"是错的——缓推的帧间位移本来就小于 1px，永远达不到 0.6。
**只把 0–0.03 当真冻帧处理。**
